# 阶段 1–2：会话、角色与资产界面

阶段 1 先保留一条可见产品路径：角色选择、会话选择、消息阅读和消息发送。阶段 2 在这条路径上恢复顶栏工具和 Plugin 资产浏览/编辑；消息生成仍由固定流式 mock 驱动。

![阶段 2 会话与资产概念图](/images/conversation-plugin-stage2-concept.png)

## 界面结构

- 应用最上方的通用标签顶栏保留资源标签、可拖拽区域和桌面最小化/最大化/关闭按钮；设置入口归入下方会话顶栏的右侧操作区。
- 顶栏左侧依次为角色头像与角色名、会话名称；两者分别打开角色管理和会话管理浮层。
- 会话顶栏透明并标记为 `data-tauri-drag-region`；右侧依次为无文字标签的设置、定时任务、搜索、资产和更多按钮。角色、会话入口不显示折叠状态图标。
- 主画布概念上分为左、中、右三个浮动区域。中间区域固定最大宽度 `724px`，承载消息气泡和 Composer；线程的 ScrollArea 仍覆盖整个主画布，因此滚动条保持在窗口最右侧。
- Composer 浮动在中间区域底部，宽度尽可能占满但不超过 `724px`，默认最小高度 `124px`，内容增多时自动长高并在达到编辑器上限后内部滚动。获得焦点时不增加高亮环；Milkdown 在所有主题下保持透明背景。

## 管理浮层

- 会话管理：约 `20rem` 宽，包含搜索、独立 `+` 新建按钮和固定高度的 ScrollArea 会话列表；悬停行显示置顶和删除。
- 角色管理：约 `23rem` 宽，搜索框、独立 `+` 新建按钮和列表/卡片切换按钮组彼此分开；列表模式为单竖列，头像后显示名称和单行省略描述；卡片模式平铺头像，名称位于左下，悬停上浮描述。
- 窄于 768px 时，浮层限制为视口宽度，角色列表退化为单列，角色卡片为两列，触控操作按钮保持可见。

## 阶段边界

- 角色、会话、置顶、删除、搜索和视图切换仅使用当前运行期 mock 数据。
- 发送消息后创建用户消息，并把固定 Markdown 回复按增量写入助手消息。
- 资产面板使用真实 Plugin Store 和稳定节点树；Tauri 桌面环境正常读写数据库，纯 Vite 预览使用同一内置树的内存状态。
- Backup 初始化、完整工作区注册和真实模型仍不进入当前可见路径。

## 阶段 2 资产交互

- 资产按钮控制右侧概念区域内的浮动卡片；卡片与窗口右侧和中间区域均保留间隙，使用圆角、完整边框和最大高度，从右侧移入且不占据布局宽度。面板标题为“资产”，右侧只有导入按钮，文件树在有界 `ScrollArea` 中支持多层展开。
- 点击文件在资产面板左侧打开默认约 `600 × 720px` 的编辑浮窗，并保留约 `16px` 间距；桌面端允许双向拖拽缩放，内部编辑区域随浮窗剩余高度铺满，窄于 768px 时回退为不可缩放的视口内全宽浮层。
- Markdown 文件继续使用项目本地 Milkdown/Crepe；JSON、JavaScript 和普通文本提供源码编辑，媒体文件提供预览。
- 保存通过 Plugin Store 更新当前稳定文件节点；搜索入口可以同时定位角色、会话和插件资产。

应用正文使用 `-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif` 系统字体栈；Windows 10/11 已自带 Segoe UI，无需额外下载。
