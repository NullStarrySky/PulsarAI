# PulsarAI 核心系统事实来源

> 本文档是角色包、会话与插件三大核心系统的唯一事实来源。所有定义与规则均为强制性要求；
> 与本文冲突的其它描述以本文为准。

---

## 角色包

<region #goal>
角色包是用户角色、会话与本地资源的归属边界：

- 作为用户角色、Conversation 和本地资源的拥有者；
- 选择当前角色使用的主插件（`mainPluginId`）与启用的全局插件（`enabledGlobalPluginIds` 无序集合）；
- 为导入、导出、同步和删除提供完整资源边界。

角色包不是系统角色，也不是插件内容的副本。每个角色包恰好拥有一个本地插件；
Conversation 通过 `packageId` 归属角色包，插件通过稳定 ID 与角色包建立关系。
</region>

<region #design>
- **数据归属**：角色包不保存 Conversation 数组；Conversation 的 `packageId` 是归属关系的唯一事实来源。
  分类只用于组织角色包，不影响生成、权限或插件解析。
- **生命周期**：创建角色包时在同一事务中创建其本地插件，并默认将该插件设为主插件。
  删除角色包时同时删除所属 Conversation、本地插件和派生数据，但不删除全局插件。
  删除分类只会令其中角色包变为未分类。
- **来源别名**：角色包可保存可选的稳定 `nickname`。SillyTavern 角色卡导入时以不含扩展名的
  原文件名作为 nickname；导入后资源寻址与导航始终使用稳定 ID，绝不回退到 nickname 匹配。
- **主插件切换**：`setMainPlugin()` 会自动启用目标全局插件；主插件不能被直接停用，必须先切换。
- **备份边界**：版本管理以角色包为完整资源边界做快照与恢复；导入资源副本时父子 ID 成对重映射。
</region>

## 会话

<region #goal>
会话系统拥有对话及其消息的完整生命周期：双层消息结构、分支与版本、生成请求闭环、
资源 Overlay 重放、不可变压缩记忆与外部 Agent 对话 API。

Conversation 只提供生命周期与底层 API，**不组装模型最终上下文**；上下文由主插件
`generatePath` 指定的生成脚本通过 `imports`、`run` 和 `ctx` 自行构建。
</region>

<region #design>
- **归属与绑定**：每个会话必绑定角色包（`packageId`）。`binding` 只持久化稳定资源关系 ID
  （资源类型 + 数据库节点 ID），标题、路径、所属包在读取时解析。`kind`（`chat`/`test`）承担
  硬语义；测试会话是绑定插件的数据库会话，测试数据不写入插件树。`rendererId` 选择会话渲染器，
  模板克隆消息路径时继承。
- **双层消息结构**：逻辑节点 `ChatMessageContainer` 管理角色、树形拓扑与分支（仅一个父节点、
  无分支合并、同时只有一个激活 `activeMessage` 版本）；具体版本 `ChatMessage` 持有正文、类型、
  调试与重放元数据。活动路径沿 `activeNextContainer` 指针延伸；可用分支由 `previousContainer`
  反向查询，不维护第二份子 ID 数组。重生成在容器内追加并激活新版本，旧版本保留。
- **初始化**：角色包、分类、会话与消息容器并行读取后一次性提交；空数据库保持空状态，
  不创建默认角色包或自动选择第一项。
- **临时对话**：`temporary: true` 的纯内存 `test` 对话，使用真实角色环境、测试目标插件作为
  主插件；不入数据库、普通列表与同步备份，在显式销毁或发起它的 Agent 运行结束时释放。
- **错误消息**：`type: "error"` 的消息正常展示和持久化，正文统一 `[ERROR]` 前缀、渲染为
  destructive alert，并从生成上下文、活动路径与重生成比对输入中剔除。
- **生成配置**：模型与推理强度不写入 Conversation。生成时读取主插件 `manifest.json` 固定键
  `generation/model`（`provider/modelId/thinkingLevel`，末段可省略；省略时不传 AI SDK `reasoning`，
  并向 Sandbox 暴露 `reasoningEffort`）。背景选择只读取内置核心插件 `appearance/background`
  路径 ID，按角色本地、全局、内置顺序从 `background` 容器解析。
- **统一请求入口**：`conversation.requestContainer(...)` 是生成容器生命周期的唯一入口——
  `generate`/`command` 新建普通或隐藏命令容器，`regenerate` 在既有普通助手容器中追加并激活
  新版本，`continue`/`rewrite` 就地变更当前版本。隐藏命令容器恰有一个版本，拒绝一切版本操作
  与 regenerate/continue/rewrite。生成路径必须使用该助手而非临时构造空容器。
- **生成完成契约**：`generatePath` 返回值不参与消息内容。流程通过目标绑定的 `reply` 闭包写入
  正文、部件、步骤与实际模型名；流式逐段 `appendContent`，流结束后可 `read()` 取全文做正则等
  后处理再 `setContent` 写回。`fail` 与其它错误入口统一追加 `[ERROR]` 前缀。
- **资源 Overlay**：生成前复制可见插件树并沿活动路径重放 `meta.resourceUpdate.operations`
  （plugin-node edit/create/move/remove 与 `.data` 实例纯 JSON 编辑）。生成沙箱的
  `write/edit/mkdir/move/remove/config.set` 只改 Overlay；`codeAct` 是唯一模型工具，其文件与
  Data 操作在同一事务内原子提交或回滚。插件根的创建、移动、删除永远在 Overlay 之外。
- **Data 定义**：`.data.json` 声明隔离级别（`resource`/`conversation`）、`initialValue`、
  `wrapperSource`、说明、`enableUpdater` 与可选 `varName`；包装器基于纯 JSON 运行值返回唯一
  facade，`replace` 产生普通 Overlay 操作，不回写定义文件。
- **压缩记忆**：基于活动路径派生的不可变索引，不改写正文与分支拓扑。最近阈值窗口与含
  error/特殊 parts 的区间保留原文；摘要精确记录容器/版本 ID，高层可引用低层；读取时递归校验
  哈希与连续性，失败整体回退原文并返回诊断。`compressionThreshold` 由生成流程从主插件配置
  显式读取（内置插件换算为 0–100% 上下文保留比例，≤0 直接返回原文）。删除会话物理清理全部
  压缩段。
- **并发安全**：并发生成串行化；生成流运行中禁止再次触发自身，防止死循环生成。
</region>

## 插件

<region #goal>
插件是数据库中的元信息加嵌套 `root` 文件树，是可编辑的资源与执行语义载体：

- 以 `manifest.json`（配置与 `runtime/generatePath`）、`containers.json`（容器声明）、
  `regex.json`、`*.chat.json`、`*.data.json`、`tools/`、`components/`、`action/`、`background/`、
  `temp/` 等约定承担固定职责；
- 通过显式导入（`imports` facade、顶层 FS 函数、`container.*`、`config.*`）向生成流程供给资源；
- 每个角色包一个本地插件，全局插件（`packageId: null`）跨角色共享；内置插件可编辑、可恢复。
</region>

<region #design>
- **归属与冲突**：角色包通过 `mainPluginId` 指定主插件并以 `enabledGlobalPluginIds` 启用全局
  插件。同一作用域内容器、工具或资源注册冲突直接报错，不进行覆盖；不同插件的同名文件由
  可编辑的插件 ID（容器成员路径 `<pluginId>/<插件内路径>` 的顶层段）命名空间区分。
- **持久化**：`resource_plugins` 存插件元信息，`resource_plugin_nodes` 存扁平稳定树节点
  （ID、父关系、路径、`treeOrder`、文件 `order`、单目标 `insertion`、内容）；插件写入时在单
  事务内重建路径与检索索引。文件 `order` 默认 100，同值以稳定 ID/路径为确定性 tie breaker。
- **执行语义**：系统不存在"主上下文入口"。`generatePath` 是唯一固定入口，自行决定读取哪些
  资源与容器、是否应用 `depth:*`/`CTX_BUILD`/`CTX_PROCESS_BEFORE_REGEX`/`REGEX`、是否调用模型。
  A main plugin 必须暴露有效 `runtime/generatePath` 才能被选为主插件。
- **容器**：容器是惰性资源注册表，成员由文件 `insertion.target`（可选同步 JS 条件或
  `conditionPath`）声明；`selectionMode`（single/multiple/none）与 `overrideStrategy`
  （override/merge/intersection）驱动选择解析。容器成员注册不自动参与生成。重复插件 ID、
  插件内重复路径、缺失导入、非法 JSON、循环引用必须报错并产出含 pluginId/resourceId/path
  的完整诊断，不做 last-write-wins 合并。
- **导入与执行**：`import` 解析文本宏（`{{ }}` 字符串 / `[[ ]]` 数组）与 `.chat.json`、
  `.data.json`，不执行代码；`run` 显式执行 `.js`（或打开 `.vue` 预览）；`test` 提供 AST 追踪
  诊断。宏与 JS 共用 `imports` facade 与 URI 前缀（`@/` 本地插件、`@<pluginId>/` 目标插件）；
  环境参数接受会话 ID 或显式环境对象。
- **Data 与工具**：`.data` 导入返回水合 facade；`tools/<name>/tool.js + prompt.md` 注册为
  `ctx.tools[name]` 并注入单一 `# 自定义工具` 系统块——它们与 Skill/MCP 一样是上下文函数，
  不是额外模型工具；`codeAct` 是唯一模型可见工具。
- **正则**：根 `regex.json` 注册到有序 `REGEX` 容器；生成不自动应用，渲染可复用
  `applyOnRendering` 规则但绝不把渲染结果写回消息内容。
- **背景**：`background/` 媒体注册到 `selectionMode: "single"` 的 `background` 容器；
  选择经由容器单选（本地优先于全局），不编码为 CSS 片段。
- **内置插件源码**：`builtIn/` 目录是插件数据而非应用源码，需从 TS 扫描排除；
  `.pulsar-plugin.json` 以相对路径映射稳定节点元信息，映射文件与 `.gitkeep` 不属于插件资源。
- **API 裁剪**：`environment.plugin` 与顶层 FS 函数完整装配；仅被明确分类为破坏性、外部副作用、
  付费或任意执行的方法从运行时实例移除，而非只隐藏文档。
</region>
