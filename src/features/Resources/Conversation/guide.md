# 对话系统

PulsarAI 的对话不是一段扁平字符串列表，而是一棵可切换版本和分支的消息容器树。Conversation Feature 负责可见消息路径、编辑与重生成、附件和动作，并把一次生成交给现有 Plugin、Sandbox、Capability 和 Agent 链路。

## 核心对象

### 角色包

角色包是对话、插件顺序和权限覆盖的归属边界。它保存：

- 名称、图标、描述、分类和排序；
- 所属对话；
- 本地插件与外部全局插件顺序；
- 可选的 Feature API 权限覆盖；
- 可选的同步配置。

角色包没有权限覆盖时继承默认权限。某个 Feature 的显式空权限列表表示拒绝该 Feature 的全部外置 API。

### 对话

一条 Conversation 保存：

- `packageId`：所属角色包；
- `kind`：`chat`、`task` 或 `test`，表示普通、任务或插件测试语义；
- 可选的 `binding`：关联资源的所属包、类型、ID、路径、标题和插件 ID；
- `title`：对话名称；
- `rootContainerId`：消息树根节点；
- `lastContainerId`：当前有效路径末端；
- `rendererId`：标准对话或小说阅读器；
- `reasoningEffort`：当前会话的模型思考深度；
- `isTemplate`：是否为角色包模板；

每个角色包最多有一个模板对话。新建对话时会克隆模板的消息路径和渲染器，并为所有容器与消息重新映射 ID。

### 消息容器

`ChatMessageContainer` 表示树上的一个角色节点：

- `role` 为 `system`、`user` 或 `assistant`；
- `content` 保存同一节点的多个消息版本；
- `activeMessage` 指向当前版本；
- `availableNextContainer` 保存后续分支；
- `activeNextContainer` 选择当前分支；
- `previousContainer` 指向父节点。

当前对话路径由根节点沿 `activeNextContainer` 走到末端。切换消息版本和切换分支是两件不同的事。

## 消息版本与分支

同一容器可以保存多个版本。重生成助手消息时，新结果会追加到当前容器的 `content`，原结果不会立即消失。界面可以左右切换版本，也可以删除当前版本。

编辑历史消息或从历史位置继续时，系统会创建或切换后续分支，避免覆盖原来的对话路径。分支选择保存在上一个容器的 `activeNextContainer`。

因此：

- “版本”是同一角色节点的多个候选内容；
- “分支”是从某个节点开始的不同后续路径；
- 当前生成只读取当前激活路径。

## 消息内容

一条 `ChatMessage` 保存语义类型、主要 Markdown 内容、生成元数据、可选 parts 和可选收藏状态。`type: "message"` 表示普通消息，`type: "error"` 表示错误提示；旧数据加载时会补全为普通消息。`favorite` 属于具体消息版本，同一容器的不同版本可以独立收藏。

支持的附加 part 包括：

| 类型 | 用途 |
| --- | --- |
| `text` | AI SDK 文本内容 |
| `image` | 图片输入 |
| `file` | 文件附件 |
| `action` | 当前用户消息选择的插件动作 |
| `component` | 回复中的已注册界面组件 |

生成元数据记录模型名称、开始时间、耗时、插件身份、角色包身份、实际解析的资源 ID、诊断和工具步骤。

## 输入框

输入框负责普通文本、插件动作和附件。

### 动作

在输入开头键入 `/` 会打开启用插件的命令列表。JavaScript 命令选择后：

- 一条用户消息最多保存一个 `ActionPart`；
- ActionPart 总是第一个 part；
- 剩余用户文本作为 `prompt`；
- 动作文件只替换当前一次生成的流程入口。

`action/` 下的 Markdown 命令不会发送消息。选择它，或直接提交完整的 `/命令名`，都会把文件正文填入输入框并保留待发送附件，之后仍可自由编辑。

### 附件

文件附件使用 AI SDK `ModelMessage` 的 file part 形态，保存：

- base64 数据；
- IANA `mediaType`；
- 可选文件名；
- 本地显示大小。

发送前附件显示在输入框上方。已经发送的用户消息也可以添加或移除附件，修改会持久化并参与后续有效路径。

### 工具栏

输入框工具栏由外观设置统一管理：

- `left`：输入框左侧工具；
- `right`：输入框右侧工具；
- `unused`：隐藏工具。

当前工具目录包括模型选择、思考深度、附件、白板、会话地图和全屏输入。新工具需要加入统一目录并获得默认或迁移位置。

### 思考深度

输入栏的思考深度按钮使用五档滑块，并按当前会话持久化：

| 界面档位 | AI SDK `reasoning` |
| --- | --- |
| 关闭 | `none` |
| 低 | `low` |
| 中 | `medium` |
| 高 | `high` |
| 超高 | `xhigh` |

新会话默认关闭；从模板创建时继承模板档位。生成开始后，`reasoningEffort` 会进入 Sandbox 上下文，`agent.prepare()` 同时返回对应的 `reasoning`。Conversation 绑定的 `ToolLoopAgent` 构造器会把它作为 AI SDK 顶层参数传入，因此已保存的内置流程也能立即使用；新的内置流程源码仍显式写出 `reasoning: runtime.reasoning`。

### 会话地图

工具栏中的 `map` 会打开当前会话的无合并分支图。每个 `ChatMessageContainer` 都是独立节点，节点之间只根据单一的 `previousContainer` 连接；`availableNextContainer` 只决定同级分支顺序，不会把分支重新合并。

当前激活路径会高亮。地图顶部搜索当前会话中的全部消息版本；输入关键词后，消息预览列表会覆盖分支画布，收藏结果排在普通结果之前。点击节点或搜索结果后，系统会选中对应消息版本，依次切换该节点祖先上的 `activeNextContainer`，保留并继续跟随节点自身已有的激活后代，然后：

- 标准渲染器滚动到点击的消息；
- 小说渲染器切换到对应助手章节，用户或系统节点则选择其后的最近助手章节。

地图使用可横向和纵向滚动的画布；窄窗口下弹层占满可用窗口，节点仍保持可触摸尺寸。

### 消息收藏

标准消息渲染器的更多菜单可以收藏或取消收藏当前消息版本。收藏状态随消息持久化，并在设置的“会话 / 消息收藏”页面集中显示。

点击收藏页面中的记录会打开所属会话、恢复记录所在的消息版本和分支，再复用与会话地图相同的定位请求滚动到目标消息；小说渲染器会切换到对应章节。

## 一次生成如何运行

一次生成使用固定启动顺序：

1. 过滤当前路径中的 `error` 消息，再把剩余容器转换为保留角色的 AI SDK 消息。
2. 创建空的助手目标容器和空消息。
3. 解析默认 Feature API 权限与角色包覆盖，把当前会话的 `reasoningEffort` 加入上下文并构建最小 Sandbox 环境。
4. 索引当前可见且启用的插件、根 `containers.xml`、文件成员元数据和显式引用。
5. 从根 `context.imd` 读取可更新变量和压缩阈值，沿激活路径重放消息版本绑定的更新函数，并更新分级压缩指针。
6. 收集 `tools/<名称>/tool.js + prompt.md`，把说明组成“自定义工具”系统区块，并准备 `ctx.tools` 函数表。
7. 用最新贫血值和压缩后的 `chat` 编译第一个可用的根 `context.imd`，并在最前面加入已授权 Feature API、变量说明和自定义工具说明。
8. 收集启用插件的根 `regex.json`，按文件优先级和稳定插件顺序对最终模型消息做正则后处理。
9. 编译自定义函数；如果当前消息选择了动作则运行该动作，否则运行第一个可用的 `agentprocess/index.js`，没有流程入口时明确报错。
10. 把结果写回已经创建的空助手消息，并持久化模型信息、耗时、工具步骤、资源追踪和诊断。

启动过程创建世界，插件流程只在已经授权和组装好的环境中运行。

## 上下文与重生成

`context.imd` 中的 `[[chat]]` 会保留当前路径原有的 system、user 和 assistant 角色。

重生成时，系统会向前寻找最近一个已经完成的旧版本。如果存在，会把它作为额外 system 消息提供给本次生成，用于减少措辞、结构和内容上的不必要重复。

页面标签在生成期间显示通用 `loading` 状态。无论用户是否切换到其他标签页，状态都会保留，并在生成结束的 `finally` 路径清除。

## 变量与压缩记忆

根 `context.imd` 中启用 updater 的数据由初始贫血值、说明和包装器组成。说明会自动进入“变量说明”系统区块；包装器把 JSON 草稿变成模型更容易正确调用的领域方法。模型可以给唯一的 `codeAct` 指定 `variable-update` 意图并提交同步函数。这个意图只拿到 `variables`，不能访问 Feature/插件 API、文件、网络、当前时间、随机数或异步后台任务。

更新先在完整克隆的草稿上执行并检查仍为 JSON 值。失败会整笔回滚并返回模型修正；连续第三次失败抛错。成功函数按调用顺序组合并绑定当前助手消息版本。后续生成从 IMD 初始值出发，只重放激活路径上带更新的消息；有界内存缓存保存更新节点状态，不给每条消息持久化快照。切换分支或消息版本会自然换一条状态链。

`memory.compression_threshold` 为 0 时关闭压缩。启用后，最新一个阈值窗口保持原文，更早的固定区间由快速模型并行摘要；带附件、组件或动作 part 的区间暂时保持原文，避免丢失富内容。每四个相邻同级摘要又可以生成父摘要。叶摘要记录精确容器与消息版本，父摘要记录子指针。读取时递归验证指针并优先跳到覆盖最远的合法摘要；任何压缩失败都回退当前轮的原始消息。摘要不会改写消息内容或分支关系，删除对话时一并清理。

## Agent 资源、Skill、MCP 与自定义工具

Agent Feature 提供 `ToolLoopAgent` 构造器和惰性 `agent.prepare()`；模型、唯一的 `codeAct` 工具、停止条件和生命周期钩子只在流程明确准备 Agent 时加载。内置插件的可编辑 `agentprocess` 明确执行 `new ToolLoopAgent(...)`；自定义流程也可以选择不使用 Agent。

Skill 和 MCP 不会创建第二条生成路径，也不再各自成为模型工具。它们保存在 Agent extension registry，并通过 CodeAct 上下文中的 `agent.callExtension(...)`、`skills.call(...)` 或 `mcp.call(...)` 调用；摘要和兼容名称仍可从 `skills.list()`、`mcp.list()`、`skills.tools` 与 `mcp.tools` 查询。

插件自定义工具同样不会增加模型工具数量。模型从“自定义工具”系统区块读取 `prompt.md` 说明，再在 CodeAct 函数中执行 `await ctx.tools[名称](...参数)`。文档区块保留来源插件、`tool.js` / `prompt.md` 的资源 ID 与路径，便于继续检查定义。

需要用户决定时，模型在 CodeAct 函数中调用 `await agent.askUser(...)` 或 `await api.askUser(...)`。调用后：

1. 对话生成暂停；
2. 界面打开 `agent.ask-user` 组件；
3. 用户选择预设项或输入自由回答；
4. 结果成为当前 CodeAct 函数返回链路的一部分；
5. Agent 从同一次运行继续。

## 生成组件

生成组件通过 generation component registry 注册。

- `api.askUserWithComponent(...)` 打开组件并等待 `resolve` 或 `cancel`；
- `api.renderComponent(...)` 把组件 part 写入当前助手消息；
- 消息渲染器在 Markdown 下方渲染这些组件。

插件中的 `.vue` 文件只是资源源码，不会自动进入注册表。

## 对话渲染器

每条对话独立保存 `rendererId`。

### 标准对话

标准渲染器展示当前有效路径中的消息气泡、版本控制、分支控制、编辑、复制、收藏、翻译、附件和生成步骤。

消息列表使用 shadcn-vue 的 `MessageScroller`、`Message` 和 `Bubble` 组合，附件使用 `Attachment`，错误提示使用 destructive `Bubble` 与带标签的 `Marker`。消息路径通过 `@tanstack/vue-virtual` 只挂载可视区域和 overscan 行，并用 `measureElement` 持续测量 Markdown、步骤折叠和流式回复产生的动态高度。滚动容器仍会跟随流式回复，并在用户离开底部时提供回到最新消息的按钮；地图与收藏跳转先按消息索引驱动虚拟列表，再定位已挂载行。

在“设置 / 外观 / 交互式代码预览”启用后，消息 Markdown 中的 fenced code block 只要包含 `<html>`、`<!DOCTYPE>` 或 `<script>`，就会渲染成可交互 `srcdoc` iframe。iframe 允许脚本、表单和弹窗，但不授予 `allow-same-origin`，因此无法直接访问宿主页面。当前路径最后一条消息会用预览替换整条正文；旧消息保持 Markdown 与预览混排。每个预览都可以切回完整源码。该开关默认关闭并随外观设置保存在本机。

翻译不会再不可逆地覆盖消息。第一次翻译时，原文与翻译时间保存在 `message.meta.translation`；更多菜单随后显示“还原原文”。手动编辑消息会清除这份翻译快照，避免还原到已经失效的内容。

标准会话、小说阅读器和任务面板都会读取当前角色包启用插件的正则容器，但只应用 `applyOnRending: true` 的规则。处理发生在显示副本上，不会把替换结果保存回原消息。

生成流程抛出的异常会把当前助手消息标记为 `error`。获准使用 Conversation 发送能力的外部脚本也可以调用 `await conversation.pushErrorMessage(content)` 追加错误消息。错误仍保留在界面和数据库中，但不会进入下一轮的 `chat`、生成环境 `activePath`、重生成比较输入或绑定对话资源快照。

### 小说阅读器

小说阅读器把有效路径中的每个助手容器视为一章：

- 提供上一章、下一章和章节选择；
- 折叠显示最近的用户提示；
- 使用居中的阅读版式；
- 保留当前章节的生成组件；
- 在窄窗口使用更紧凑的排版。

模板对话也保存渲染器，新对话克隆模板时会继承它。

## 项目 Agent 对话

项目空白页在用户第一次发送消息前不持久化对话，也不存在用于收纳任务的内置角色包。用户可以选择已有角色包，或者输入名称后新建角色包，并选择普通对话或任务对话。

首次发送时，系统会：

1. 在选中或新建的角色包中创建对话；
2. 保存 `kind`，任务对话同时保存指向 `/project.json` 的 `binding`；
3. 生成不冲突的对话标题；
4. 打开普通 Conversation 工作区；
5. 通过同一条插件与 Agent 生成链路发送消息。

项目的读取和修改能力由 Agent Feature 提供，不由 Conversation 复制一套 CRUD。

### 任务与资源上下文

右侧栏的“任务”页签会跟随当前主工作区标签：

- 项目对话对应 `/conversations/<id>.json`；
- 项目本地插件对应 `/plugins/<pluginId>`；
- 在插件工作区切换文件时，路径继续细化到当前选中文件。

任务页签顶栏的下拉菜单负责选择、新建、重命名、删除和在主工作区打开关联会话。任务以 `kind: "task"` 保存在当前项目角色包中，`binding` 记录项目和具体资源路径；插件资源则创建 `kind: "test"` 的测试会话。切换主页面后，列表自动显示新项目、新路径下的关联会话。

任务会话直接在侧栏中使用与普通对话相同的输入组件发送消息，不会切换主页面当前打开的对话。生成时会加入：

- 当前资源的类型、ID、路径与所属包；
- 插件元数据、当前插件文件、根 `info.md` 和 `AGENTS.md`；
- 对应的 Conversation 或 Plugin Feature 文档。

插件资源创建 `kind: "test"` 的测试会话。真实消息历史只保存在数据库并通过 `pluginId` 关联，不写进插件文件树；全局插件创建测试会话时必须选择一个已有角色包作为执行环境。删除插件时会一并删除这些关联测试会话。

## 常用操作与快捷键

| 操作 | 默认快捷键 |
| --- | --- |
| 新建对话 | `Ctrl+N` |
| 刷新应用 | `Ctrl+R` |
| 清空角色包数据并刷新（保留设置） | `Ctrl+Shift+R` |
| 重生成最后一条消息 | `Ctrl+Shift+G` |
| 全局搜索 | `Ctrl+K` |
| 关闭当前标签页 | `Ctrl+W` |
| 下一个标签页 | `Ctrl+Tab` |
| 上一个标签页 | `Ctrl+Shift+Tab` |

编辑、复制最后一条消息等动作也注册在统一命令系统中，可以从搜索面板执行或在快捷键设置中绑定。
