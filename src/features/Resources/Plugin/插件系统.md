# PulsarAI 插件系统架构

> 本文档是 PulsarAI 插件系统架构的唯一事实来源。所有定义、约束与执行边界均为强制性要求。

---

## 1. 核心关系与生命周期

- **归属关系**：每个角色包拥有一个本地插件，该插件的 `packageId` 指向角色包；角色包通过 `mainPluginId` 指定主插件，并通过 `enabledGlobalPluginIds`（无序集合）启用全局插件。
- **角色包契约**：完整定义见 [`../CharacterPackage/角色包.md`](../CharacterPackage/角色包.md)。
- **全局冲突**：同一作用域内的容器、工具或资源注册冲突时直接报错，不进行覆盖。
- **可恢复性**：`builtIn`（内置）插件允许编辑，并支持恢复默认内容。
- **持久化**：数据库分别存储插件元数据和扁平的稳定树节点。节点 ID 是唯一身份标识。移动/重命名必须在单次事务中同步更新路径与索引。

## 2. 统一数据模型

### 2.1 插件树节点 (PluginNode)
```ts
export interface PluginNode {
  id: string; // 稳定节点 ID
  pluginId: string; // 所属插件 ID
  path: string; // 插件内绝对路径
  name: string; // 节点名称
  icon: string; // 展示图标
  kind: "file" | "folder"; // 节点类型
  treeOrder: number; // 树形 UI 展示顺序
  children?: PluginNode[]; // 仅文件夹有效
  // 以下字段仅在 kind === "file" 时有效
  content?: unknown; // 文件内容 (在 read 或 readMeta 阶段可选加载)
  order?: number; // 容器内排序权重，默认 100
  insertion?: {
    target: string; // 目标容器 ID (如 "character" 或 "depth:0")
    condition?: string; // 插入条件；由列表编辑器生成，可通过 API 直接写 JS 布尔表达式
  };
}
```

### 2.2 插件实体 (Plugin)
```ts
export interface Plugin {
  id: string; // 可编辑的插件标识，也是容器资源完整路径的顶层路径段
  packageId: string | null; // null 表示全局插件
  name: string;
  icon: string;
  description: string;
  root: PluginNode; // 根节点 (kind: "folder")
  enabled: boolean;
  builtIn: boolean;
}

export type PluginSummary = Omit<Plugin, "root"> & {
  local: boolean;
  main: boolean;
  active: boolean; // 是否在当前激活的插件集合中
};
```

### 2.3 容器模型 (PluginContainer)
```ts
export interface PluginContainer {
  id: string; // 容器 ID (内置容器如 "character"，或深度容器 "depth:K")
  title: string; // 展示名称；业务逻辑不得依赖本地化标题
  pluginId: string; // 声明容器的插件 ID (内置容器为 "system")
  scope: "local" | "global"; // 作用域
  description: string; // 单行用途说明
  contentSuffixes: string[]; // 允许的后缀。"*" 代表不限，"media" 代表媒体格式
  resources?: PluginContainerResource[]; // 已索引的资源列表 (仅在查询结果中包含)
}

export interface PluginContainerResource {
  id: string;
  pluginId: string;
  name: string;
  path: string;
  order: number;
  content?: unknown; // 仅在 readContainer 时返回
}
```

容器是资源注册表：成员可被索引、显式导入或由用户选择，但不会自动参与生成。容器成员使用 `<pluginId>/<插件内路径>` 作为完整路径，例如 `builtin-core-plugin/regex.json`；`pluginId` 是可编辑的顶层路径段，不是自动生成的资源 UUID。不同插件中的同名文件不会冲突。`depth:*` 只表达消息插入位置；是否读取和插入仍由生成流程决定。后缀匹配忽略大小写并优先匹配复合后缀；`[]` 表示不接受文件。

### 2.4 插入条件

插件文件编辑器使用列表编辑器配置条件：可选择“全部满足（AND）”或“任一满足（OR）”，每条条件选择函数并填写参数；关键词条件统一设置检查最近多少条消息。列表最终保存为 `insertion.condition` 的 JavaScript 布尔表达式，不增加第二份条件元数据。

解析容器成员时，条件在当前资源作用域内同步执行。环境包含该资源的 `imports`、当前生成环境，以及以下固定函数：

- `include(keywordOrRegex, depth?)`：最近 `depth` 条消息包含关键词或匹配 `/pattern/flags` 时返回 `true`；省略深度时检查全部消息。
- `exclude(keywordOrRegex, depth?)`：`include` 的反向判断。
- `probability(percentage)`：按 `0` 至 `100` 的百分比返回布尔值。
- `containKeyWord`、`excludeKeyWord`：分别是 `include`、`exclude` 的兼容别名。

条件为空时始终注册资源。条件返回假时只跳过该资源；条件执行报错时跳过该资源并记录诊断，不中断其它资源的索引。`condition` 必须同步返回可转为布尔值的结果，不得启动异步任务。

## 3. 文件与目录语义约定

除了以下约定路径外，其它文件与目录可自由命名组织。容器关系由第 4 节统一规范，不允许附加转换或执行模板。

根级 `manifest.json`、`containers.json`、`regex.json` 等约定文件必须按精确路径识别，不可重命名、移动或删除。

### 3.1 约定配置文件格式

#### manifest.json (唯一配置)
```ts
export type PluginManifest = {
  group: { id: string; title: string };
  content: {
    id: string;
    title: string;
    description: string;
    component: "Switch" | "Checkbox" | "Input" | "Textarea" | "Select" | "Slider" | "ModelSelect" | "MediaSelect" | string;
    props?: Record<string, unknown>;
    value: unknown; // 合法 JSON 值
  }[];
}[];
```
- **`runtime/generatePath`**：普通插件可以不配置，但不能被选为主插件。配置后，其值必须指向存在且有效的 `.js` 脚本，否则报错。
- **`generation/model`**：模型引用使用 `provider/modelId/thinkingLevel`；值为空时继承全局默认聊天模型，`thinkingLevel` 可省略并支持 AI SDK 的 `none`、`minimal`、`low`、`medium`、`high`、`xhigh`。
- **`appearance/background`**：背景资源引用 `{ pluginId, path }`。值为空、键不存在或资源无效时读取内置核心插件的同一固定键。
- **compressionThreshold**：普通配置项，由使用它的资源通过 `imports.config.local` 读取，不属于元数据。

以上路径是系统直接引用的固定键；其它 Group/Content 仍是插件自定义配置。

`component: "ModelSelect"` 使用应用的模型选择器编辑配置值。聊天值为 `providerId/modelId/thinkingLevel` 字符串，末段可省略；`null` 显示全局默认聊天模型，并允许恢复继承。可通过 `props.apiType` 限制模型类型，取值为 `chat`、`image`、`video`、`embedding`、`asr` 或 `tts`，默认 `chat`。

会话输入区工具栏提供“主要插件” `Select`。候选项只包含当前角色包的本地插件和全局插件，并且必须具有有效的 `runtime/generatePath`；选择全局插件时会同时将其加入角色包的启用集合。

#### containers.json (容器定义)
```ts
export interface PluginContainerDefinitions {
  containers: Omit<PluginContainer, "pluginId" | "resources">[];
}
```

### 3.2 约定资源格式
- **`AGENTS.md`**：可选的 Agent 说明文件，内容格式自定；`info.md` 没有特殊语义。
- **`*.chat.json`**：可由生成流程读取的带角色上下文资源：
  ```ts
  export interface ChatContext {
    message: { role: "system" | "assistant" | "user"; content: string }[];
  }
  ```
- **`*.data.json`**：(属于 DATA 容器) 可水合的数据定义：
  ```ts
  export type PluginDataValue =
    | string | number | boolean | null
    | PluginDataValue[]
    | { [key: string]: PluginDataValue };

  export interface PluginDataDefinition {
    description: string;
    initialValue: PluginDataValue;
    wrapperSource: string; // 包装器函数源码字面量
  }
  ```
- **`regex.json`**：(属于 REGEX 容器) 排序正则规则：
  ```ts
  export interface PluginRegexRule {
    find_regex: string; // 正则源码或包含修饰符的 /pattern/flags
    replace_regex: string;
    range: "user_input" | "ai_output" | "all";
    depth_min: number | "INF"; // 倒数消息深度
    depth_max: number | "INF";
    applyOnRendering: boolean; // 是否应用于 UI 渲染
  }
  ```
- **`tools/`**：自定义工具文件夹。`tools/<name>/tool.js` (导出函数) 与 `tools/<name>/prompt.md` 同时存在时注册为 `ctx.tools[name]`。
- **`components/`**：Vue 模板组件，禁止 `<script>` 执行。
- **`action/`**：JS Action 使用生成流程的执行方式、没有返回值，错误直接抛出并通过 Notivue `push` 通知；Markdown Action 只将内容写入输入框草稿。
- **`background/`**：用户背景素材 (媒体类型)，目录内媒体注册到 `background` 容器。
- **`temp/`**：Agent 运行时生成文件的存放目录。

自定义工具是 Sandbox 上下文函数，不是额外的模型工具；`codeAct` 是唯一模型可见工具。

### 3.3 内置插件源码

`src/features/Resources/Plugin/builtIn/` 保存可编辑的内置插件源码；`.pulsar-plugin.json` 使用相对路径映射稳定节点元信息。映射文件和 `.gitkeep` 不属于插件资源。运行时映射必须保留稳定 ID、目录关系、顺序、优先级和容器成员关系。

该目录属于插件数据而不是应用源码，必须从 TypeScript 源码扫描中排除；Vite 仍需通过 `application/builtin-plugins.ts` 的 raw / URL glob 将目录内容作为发布资源打包。

## 5. 显式导入与 Sandbox API

跨资源访问必须显式声明，不支持静默全局平铺。Markdown/文本宏 `{{ expression }}` 转为字符串，`[[ expression ]]` 展开为数组，其无角色项继承父级。JavaScript 不执行文本宏，而是在运行时直接调用 `imports`，不要求资源预先插入容器。

### 5.1 导入 Facade (imports)
- `imports.resource(path: string)`: 按当前文件相对路径导入。
- `imports.resourceById(id: string)`: 按唯一 ID 导入。
- `imports.container(scope: "local"|"global", id: string)`: 获取指定容器。
- `imports.containers(scope: "local"|"global", pattern: string)`: 使用 glob 匹配容器（如 `"depth:*"`）。
- `imports.config.local(group: string, key: string)`: 读取本插件配置。
- `imports.config.global(pluginId: string, group: string, key: string)`: 读取全局插件配置。

`imports` 绑定发起调用的源资源。字面量参数用于静态依赖发现，运行时解析是最终结果。`imports.containers` 使用 glob：`*` 匹配任意连续字符，`?` 匹配单个字符，结果按容器 ID 稳定排序。

`imports.container(...)` 返回惰性容器对象：

```ts
interface ImportedContainer {
  get(path: `${string}/${string}`): unknown; // 完整路径：<pluginId>/<插件内路径>
  list(): { resources: string[] }; // 返回同样格式的完整路径
  toString(): string;
}
```

例如，`imports.container("global", "REGEX").get("builtin-core-plugin/regex.json")`。容器 API 不提供 `plugin(pluginId).read(...)`；同插件的普通文件继续使用相对路径 `imports.resource("./path")`。

### 5.2 插件 API (PluginApi)
```ts
export interface PluginApi {
  self(): PluginSummary | null;
  list(input?: { packageId?: string; activeOnly?: boolean }): PluginSummary[];
  get(pluginId: string): PluginSummary | null;
  main(packageId?: string): PluginSummary;

  createGlobal(input: { name: string; icon?: string; description?: string }): Promise<PluginSummary>;
  update(pluginId: string, patch: Partial<Pick<Plugin, "id" | "name" | "icon" | "description" | "enabled">>): Promise<PluginSummary>;
  remove(pluginId: string): Promise<void>;
  restore(pluginId: string): Promise<PluginSummary>;

  listContainers(input?: { packageId?: string; scope?: "local" | "global" }): PluginContainer[];
  getContainer(scope: "local" | "global", id: string): PluginContainer | null;
  readContainer(scope: "local" | "global", id: string): PluginContainer;
  readContainers(scope: "local" | "global", idPattern: string): PluginContainer[];

  files: PluginFileApi;
}
```

### 5.3 文件操作 API (PluginFileApi)
路径不带 `/` 则相对当前文件。规范化路径严禁跨出插件根目录。
```ts
export interface PluginFileApi {
  read(path: string): unknown;
  readMeta(path: string): PluginNode;
  write(path: string, content: unknown, meta?: Partial<Pick<PluginNode, "icon" | "treeOrder" | "order">> & { insertion?: PluginNode["insertion"] | null }): Promise<PluginNode>;
  edit(path: string, find: string, replace: string): Promise<PluginNode>; // 仅支持唯一精准匹配，多匹配或无匹配则报错
  exists(path: string): boolean;
  list(path?: string): PluginNode[];
  mkdir(path: string): Promise<PluginNode>;
  move(from: string, to: string): Promise<PluginNode>;
  remove(path: string): Promise<void>;
  run(path: string, environment?: Record<string, unknown>): Promise<unknown>;
  test(path: string, environment?: Record<string, unknown>, config?: Record<string, unknown>): Promise<{
    value?: unknown;
    diagnostics: Array<{ pluginId: string; resourceId: string; path: string; message: string; trace: string[] }>;
  }>;
}
```

## 6. Conversation

会话、消息版本、分支、变量更新、压缩记忆、测试操作与临时对话由 `# PulsarAI 会话系统架构` 定义。生成时，Conversation 向 `generatePath` 提供活动路径、原始角色消息、空助手目标，以及绑定该目标的回复和压缩记忆闭包；插件系统只消费这些数据与 API，不持有会话生命周期。

## 7. 生成流程边界

1. 创建空的助手目标消息。
2. 根据会话与权限构建最小 Sandbox，并索引可见插件、容器和数据。
3. 执行 `mainPluginId` 主插件配置的 `generatePath`。
4. 将目标消息状态及诊断链绑定到本次消息版本。

系统不存在“主上下文入口”。`generatePath` 是唯一固定入口；生成流程自行通过 `imports`、`run` 和 `ctx` 读取任意可见资源，构建最终上下文，选择是否应用 `depth:*`、`CTX_BUILD`、`CTX_PROCESS_BEFORE_REGEX` 与 `REGEX`，再调用模型。它也可以不使用这些容器，或引用多个上下文资源。

`generatePath` 的返回值不作为生成结果。流程通过当前空助手目标绑定的 `reply` 闭包写入正文、内容部件、过程步骤、错误状态和实际模型标识。内置 Agent 使用 AI SDK 7 的 `runner.stream()`：Agent 回调通过 `reply.addStep` 实时写入轮次和工具过程，所有 step 的 `text-delta.text` 通过 `reply.appendContent` 按到达顺序逐段写入正文；每段 reasoning 在结束后作为一个 `thinking` step 写入，不能按 token 创建步骤。流结束后可用 `reply.read()` 取得完整文本，进一步处理后再用 `reply.setContent()` 写回。Sandbox `console` 只保留对象的有界摘要；调试时显式序列化所需字段，不要记录完整自引用 `ctx`。

`CTX_PROCESS_BEFORE_REGEX` 只提供脚本索引，不规定参数、返回值或执行方式；生成流程可以使用 FxTS 组合这些脚本。渲染正则只作用于展示结果，不写回消息内容。

## 8. 诊断与限制说明

- **报错而非覆盖**：插件 ID 重复、同一插件内路径重复、资源缺失、路径越界、非法 JSON和循环引用必须终止执行并产生包含 `pluginId`, `resourceId`, `path` 和调用栈的完整诊断。不同插件内的同名文件由插件 ID 命名空间区分。
- **API 裁剪**：仅将被明确分类为破坏性、外部副作用、付费或任意执行的方法从运行时实例中移除，而非只隐藏接口声明。
