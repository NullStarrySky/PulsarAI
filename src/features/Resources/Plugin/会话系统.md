# PulsarAI 会话系统架构 (压缩版)

> 本文档是 PulsarAI 会话系统架构的唯一事实来源。所有定义与规则均为强制性要求。

---

## 1. 核心模型与生命周期

- **归属与绑定**：每个会话必绑定角色包。`binding` 记录会话关联的外部资源。测试会话采用真实角色包环境，测试数据存入 Conversation 数据库，不准作为文件写入插件树。
- **初始化**：角色包、分类、会话与消息容器并行读取后一次性提交。空数据库保持空状态；初始化不得创建默认角色包、补建插件或自动选择第一项。角色包及其本地插件只由明确的新建操作产生。
- **双层消息结构**：
  - **逻辑节点** (`ChatMessageContainer`)：管理消息角色、树形拓扑关系及分支。一个容器仅有一个父节点，可有多个子分支（无分支合并），同时仅有一个激活的 `activeMessage` 版本。活动路径由根节点沿 `activeNextContainer` 指针延伸。
  - **具体版本** (`ChatMessage`)：包含正文、类型、生成调试信息、重放更新元数据等。重生成助手消息时在容器内追加并激活新版本，旧版本保留。
- **临时对话 (Temporary)**：具有 `temporary: true` 的纯内存 `test` 对话。使用真实角色环境运行，测试目标插件作为主插件。不入数据库、普通列表与同步备份。在显式销毁或发起它的 Agent 运行结束时自动释放。
- **错误处理**：`error` 类型的消息会被正常展示和持久化，但从后续生成上下文、活动生成路径及重生成的比对输入中剔除。
- **生成配置**：模型与推理强度不写入 Conversation。生成时读取主插件 `manifest.json` 的固定键 `generation/model`；引用可用 `provider/modelId/thinkingLevel`，末段省略时不传 AI SDK `reasoning`。背景选择只读取内置核心 Plugin 的 `appearance/background` 路径 ID，并从 `background` 容器按角色本地、全局、内置顺序解析同 ID 资源。

## 2. 统一数据模型

```ts
export type Role = "system" | "user" | "assistant";
export type ChatMessageType = "message" | "error";
export type ConversationKind = "chat" | "test";

export interface ConversationResourceBinding {
  pluginId?: string;
  resourceType: string;
  resourceId: string; // 稳定资源 ID；插件文件绑定使用数据库节点 ID
}

export interface Conversation {
  id: string;
  packageId: string;
  kind: ConversationKind;
  binding?: ConversationResourceBinding;
  title: string;
  isTemplate?: boolean;
  rendererId?: "chat" | "novel";
  rootContainerId: string | null;
  lastContainerId: string | null;
  createdAt: string;
  updatedAt: string;
}

export interface ChatMessageContainer {
  id: string;
  role: Role;
  conversationid: string;
  content: ChatMessage[];
  activeMessage: number | null; // 当前激活的 ChatMessage 索引
  activeNextContainer: string | null;
  previousContainer: string | null;
}

export interface ChatMessage {
  id: string;
  type: ChatMessageType;
  content: string;
  favorite?: boolean;
  parts?: AdditionalParts[];
  meta: ChatMessageMeta;
}

export type AdditionalParts =
  | { type: "text"; text: string }
  | { type: "image"; image: string | Uint8Array | ArrayBuffer | URL; mediaType?: string }
  | { type: "file"; data: string | Uint8Array | ArrayBuffer | URL; filename?: string; mediaType: string; size?: number }
  | { type: "component"; componentId: string; props?: Record<string, unknown> }
  | { type: "action"; actionId: string; pluginId: string; pluginName: string; name: string; description: string };

export interface ChatMessageMeta {
  translation?: { originalContent: string; translatedAt: string };
  generateInfo?: { modelName: string; startTime: string; timeUsed?: number };
  environmentInfo?: {
    pluginId: string;
    pluginName: string;
    characterId: string;
    characterName: string;
    resolvedResourceIds?: string[];
    diagnostics?: string[];
  };
  variableUpdate?: {
    sources: string[]; // 按执行顺序保存的更新函数源码
    sourceHash: string;
    definitionHash: string;
    createdAt: string;
  };
  steps: Array<
    | { name: string; message: string }
    | { type: "tool-result"; toolCallId: string; toolName: string; input: unknown; output: unknown }
    | { type: "sub-agent"; name: string; status: "pending" | "running" | "done" | "failed"; message?: string }
  >;
}
```

`Conversation.binding` 只持久化关系标识。资源标题、插件节点路径和所属角色包均在读取时由稳定 ID 解析，重命名或移动节点不会制造陈旧绑定。`ChatMessageContainer` 只保存父指针和激活子指针；可用分支由 `previousContainer` 反向查询，不维护第二份子 ID 数组。

Action 的名称/说明以及 `environmentInfo` 的名称是消息生成当时的审计快照，不参与资源寻址。压缩段的首尾容器 ID 是跨层级区间索引：父段的 `source` 只含子段 ID，因此该边界不是总能由当前记录直接取首尾得到的重复字段。

## 3. 生成执行与上下文接口

Conversation 仅提供生命周期及底层 API，**不组装模型最终上下文**。生成时，由 `generatePath` 指定的生成脚本通过以下上下文自行构建 Prompt：

```ts
export interface ConversationGenerationContext {
  conversationId: string;
  packageId: string;
  mainPluginId: string;
  conversation: Readonly<Conversation>;
  reasoningEffort: "auto" | "none" | "minimal" | "low" | "medium" | "high" | "xhigh"; // 来自模型引用，省略时为 auto

  activePath: readonly Readonly<ChatMessageContainer>[]; // 沿活动消息路径的容器，不含 error 和本次空目标
  chat: readonly ModelMessage[]; // 转换自 activePath 的未压缩消息结构 (ModelMessage 包含 role, content)

  emptyContainer: Readonly<ChatMessageContainer>; // 本次生成所归属的逻辑容器
  emptyMessage: Readonly<ChatMessage>; // 本次生成的空助手消息版本
  containerId: string; // emptyContainer.id

  beforeGenerationMessage?: Readonly<ChatMessage>; // 重生成时同容器中最近的非空、非错误旧助手消息
  prompt: string; // 触发本次生成的用户输入
  action?: { pluginId: string; resourceId: string; name: string }; // 触发本次生成的会话命令

  reply: GenerationReplyApi;
  memory: ConversationMemoryApi;
  variables: Readonly<Record<string, unknown>>; // 重放后的包装变量 facade
  data: ConversationDataReadApi;
}
```

## 4. 助手目标闭包操作 API (GenerationReplyApi)

生成流程通过闭包操作本次空助手目标。闭包绑定 `conversationId` 和目标 ID；每次修改按调用顺序串行更新界面并持久化当前版本。`read()` 返回当前快照，生成结束、失败或取消后闭包立即失效。

```ts
export interface GenerationReplyApi {
  read(): { container: ChatMessageContainer; message: ChatMessage };
  setContent(content: string): Promise<void>;
  appendContent(delta: string): Promise<void>;
  addPart(part: AdditionalParts): Promise<void>;
  addStep(step: ChatMessageMeta["steps"][number]): Promise<void>;
  setModelName(modelName: string): Promise<void>;
  fail(content: string): Promise<void>; // 将本次版本设为 "error" 并写入错误正文
}
```
- **生成完成契约**：`generatePath` 的返回值不参与消息生成。流程通过 `reply` 写入正文或内容部件，也可以合法结束并保留空消息。流式调用逐段使用 `appendContent`；流结束后可通过 `read()` 取得完整正文，执行正则或其它后处理，再用 `setContent` 写回。模型的轮次、工具调用和工具结果可在生成期间用 `addStep` 持续写入，实际模型标识通过 `setModelName` 保存。`fail` 与其它 Conversation 错误入口会统一给正文添加 `[ERROR]` 前缀。

## 5. 状态变量更新与重放

- **变量定义**：在 `.data.json` 中声明稳定 Data ID、隔离级别（`resource` 独立实例 / `conversation` 会话共享）、`initialValue`、`wrapperSource`、说明和 `enableUpdater`。资源以字面量路径或稳定 ID 导入定义；状态文件不会被运行态改写。
- **更新重放机制**：
  1. 生成前，Conversation 沿 `activePath` 顺序依次提取激活消息版本的 `meta.variableUpdate`。
  2. 根据引用的定义哈希及更新源码哈希形成缓存键，优先读取有界内存缓存，否则在克隆的上一状态草稿上执行更新。若任一更新失败，终止生成。
  3. 执行完的变量状态通过 `imports` 返回包装 facade；切换分支或消息版本后按新的活动路径重新重放。
- **写入限制**：普通流程只读。修改只能通过 `codeAct` 执行 JS 的同步 `variable-update` 意图，该意图只能调用 `ConversationDataUpdateApi`，被物理禁止网络、文件、异步、时间、随机数及 Feature API 等副作用。每次更新在独立草稿上事务执行，成功项按原顺序合并到本次 `meta.variableUpdate`；失败时完整丢弃草稿并返回模型修复，连续失败三次终止本轮生成。

```ts
export interface ConversationDataReadApi {
  readForResource(resourceId: string, dataId: string): unknown;
  listForResource(resourceId: string): Array<{
    id: string; path: string; isolation: "resource" | "conversation"; writable: boolean; pluginId: string; value: unknown;
  }>;
}

export interface ConversationDataUpdateApi extends ConversationDataReadApi {
  writeForResource(resourceId: string, dataId: string, value: unknown): unknown;
}
```

## 6. 不可变压缩记忆

压缩记忆是基于 `activePath` 派生的不可变索引，不改写消息正文、版本或分支。是否使用压缩结果由 `generatePath` 决定。
- **构建限制**：最近的阈值窗口（由 `compressionThreshold` 指定）及任何含 `error` 消息或特殊 `parts`（媒体、动作等）的区间强制保留原始上下文不压缩。
- **层级摘要**：摘要记录精确关联的消息容器 ID 与版本 ID。高级摘要可引用低级摘要。
- **选用校验**：读取时通过 `memory.prepare(...)` 递归验证哈希、容器范围、消息版本与子摘要连续性。创建或校验任一步失败时，本次调用整体回退至原始未压缩消息并返回诊断，不得返回无法完整验证的混合结果。
- **生命周期**：删除会话必须物理级清理其绑定的所有压缩段。

`compressionThreshold` 由生成流程从主插件配置读取并显式传给 `memory.prepare(...)`；小于等于 `0` 时直接返回原始 `chat`，不创建压缩段。

```ts
export interface ConversationMemorySegment {
  id: string;
  conversationId: string;
  level: number;
  startContainerId: string;
  endContainerId: string;
  source:
    | { kind: "containers"; containerIds: string[]; messageVersionIds: string[] }
    | { kind: "segments"; segmentIds: string[] };
  sourceHash: string;
  content: string;
  leafContainerCount: number;
  sourceTokenCount: number;
  compressedTokenCount: number;
  status: "ready" | "failed" | "superseded";
  createdAt: string;
}

export interface ConversationMemoryApi {
  prepare(input: { compressionThreshold: number }): Promise<{
    messages: ModelMessage[];
    segments: readonly ConversationMemorySegment[];
    diagnostics: readonly string[];
  }>;
}
```

## 7. 外部 Agent 对话 API (ConversationApi)

公开于 `conversation` / `capabilities.conversation` 的功能，用于管理对话及测试流。非授权的外部/Destructive 方法在沙箱运行时会被物理裁剪。

```ts
export interface AgentConversationSummary {
  id: string;
  packageId: string;
  kind: ConversationKind;
  temporary: boolean;
  binding?: ConversationResourceBinding;
  title: string;
}

export interface AgentConversationMessage {
  containerId: string;
  messageId: string;
  role: Role;
  type: ChatMessageType;
  content: string;
  previousContainerId: string | null;
  nextContainerIds: string[];
  activeVersion: boolean;
  onActivePath: boolean;
}

export interface ConversationApi {
  listPackages(): Array<{ id: string; name: string }>;
  listConversations(packageId?: string): AgentConversationSummary[];
  create(input: { packageId: string; kind?: ConversationKind; binding?: ConversationResourceBinding; title?: string }): Promise<AgentConversationSummary>;
  createTemporary(input: { packageId: string; pluginId: string; title?: string }): Promise<AgentConversationSummary>;
  read(conversationId: string, options?: { includeBranches?: boolean; includeVersions?: boolean }): Promise<{
    conversation: AgentConversationSummary;
    activePathContainerIds: string[];
    messages: AgentConversationMessage[];
  }>;
  push(conversationId: string, input: { role: Role; content: string; previousContainerId?: string }): Promise<AgentConversationMessage>;
  send(conversationId: string, content: string): Promise<AgentConversationMessage>;
  pushErrorMessage(conversationId: string, content: string): Promise<AgentConversationMessage>;
  editMessage(conversationId: string, containerId: string, messageId: string, content: string): Promise<AgentConversationMessage>;
  deleteMessage(conversationId: string, containerId: string, messageId: string): Promise<void>;
  deleteTurn(conversationId: string, containerId: string): Promise<void>;
  activate(conversationId: string, containerId: string, messageId?: string): Promise<void>;
  regenerate(conversationId: string, containerId: string): Promise<AgentConversationMessage>;
  deleteConversation(conversationId: string): Promise<void>;
  disposeTemporary(conversationId: string): Promise<void>;
}
```

- `push` 只插入消息，不触发生成；未指定父节点时追加到活动路径末尾。
- `send` 插入用户消息和空助手目标，再执行该对话主插件的 `generatePath`。
- `editMessage` 修改指定版本并清除失效的翻译快照；`deleteMessage` 只删除一个具体版本，最后一个版本必须用 `deleteTurn` 连同逻辑节点删除。
- `activate` 必须先激活目标的祖先分支；`regenerate` 只接受助手容器，并在原容器中追加新版本。
- `disposeTemporary` 只接受临时对话且保持幂等。
- 普通生成代码只能修改当前顶层 Agent 创建的临时对话或明确授权的持久化 `test` 对话；无权修改 `chat` 或其它测试对话的方法必须从实际运行时对象中移除，不能只隐藏文档。

## 8. 其它强制性约束

- **操作安全**：并发生成必须串行化；严禁在生成流运行中通过 API 再次触发自身，防止死循环生成。
- **临时限制**：临时对话不得触发 UI 路由跳转、创建标签卡或持久化到历史。
- **引用一致性**：所有内部引用、分支变更必须依靠唯一的 ID 体系。
- **清理一致性**：删除会话必须同时清理容器、消息版本和派生压缩段；删除插件时清理与其精确绑定的持久化测试对话。
