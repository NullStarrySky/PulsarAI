# PulsarAI 插件系统架构

> 本文档是 PulsarAI 插件系统架构的唯一事实来源。所有定义、约束与执行边界均为强制性要求。

---

## 1. 核心关系与生命周期

- **归属关系**：每个角色包拥有一个本地插件，该插件的 `packageId` 指向角色包；角色包通过 `mainPluginId` 指定主插件，并通过 `enabledGlobalPluginIds`（无序集合）启用全局插件。
- **角色包契约**：完整定义见 [`../CharacterPackage/角色包.md`](../CharacterPackage/角色包.md)。
- **全局冲突**：同一作用域内的容器、工具或资源注册冲突时直接报错，不进行覆盖。
- **可恢复性与模板**：`builtIn`（内置）插件允许编辑，并支持恢复默认内容。系统内置 `Default` 插件模板（`builtin-default-plugin`），在 UI 中隐藏，创建新插件时以此为模板复制节点。
- **持久化与事实来源**：数据库分别存储插件元数据和扁平的稳定树节点。节点 ID 是唯一身份标识。对于会话中的 Overlay 覆盖结构，本条消息覆盖路径上对本地与全局插件的修改（即 JSON Edit 操作）作为事实来源与结果计算依据，不进行 upfront 预解析。

## 2. 统一数据模型

### 2.1 插件树节点 (PluginNode)
```ts
export interface PluginNodeBase {
  id: string; // 稳定节点 ID
  path: string; // 插件内相对路径 (如 "manifest.json" 或 "background/classroom.png")
  name: string; // 节点名称 (path 的最后一个路径段)
  icon: string; // 展示图标
  treeOrder: number; // 同级节点 UI 展示顺序
}

export interface PluginFile extends PluginNodeBase {
  kind: "file";
  content: unknown; // 文件内容
  order: number; // 容器内排序权重，默认 100
  insertion?: {
    target: string; // 目标容器 ID (如 "generatePath"、"context" 或 "REGEX")
    condition?: string; // 插入条件 JS 表达式
    conditionPath?: string; // 插入条件 JS 资源路径
  };
}

export interface PluginFolder extends PluginNodeBase {
  kind: "folder";
  collapsed?: boolean;
}

export type PluginTreeNode = PluginFile | PluginFolder;
```

### 2.2 插件实体 (Plugin)
```ts
export interface Plugin {
  id: string; // 可编辑的插件标识，也是容器资源完整路径的顶层路径段
  packageId: string | null; // null 表示全局插件
  name: string;
  icon: string;
  shortDescription: string;
  nodes: PluginTreeNode[]; // 扁平的插件相对路径节点列表
  enabled: boolean;
  builtIn: boolean;
  hidden?: boolean; // UI 中是否隐藏（如 Default 模板插件）
}

export type PluginSummary = Omit<Plugin, "nodes"> & {
  active: boolean; // 是否在当前激活的插件集合中
};
```

### 2.3 容器模型 (PluginContainer)
```ts
export interface PluginContainer {
  id: string; // 容器 ID (内置容器如 "generatePath"、"character"，或深度容器 "depth:K")
  title: string; // 展示名称；业务逻辑不得依赖本地化标题
  pluginId: string; // 声明容器的插件 ID (内置容器为 "system")
  scope: "local" | "global"; // 作用域
  description: string; // 单行用途说明
  contentSuffixes: string[]; // 允许的后缀。"*" 代表不限，"media" 代表媒体格式
  selectionMode?: "single" | "multiple" | "none";
  overrideStrategy?: "override" | "merge" | "intersection";
  resources?: PluginContainerResource[]; // 已索引的资源列表 (仅在查询结果中包含)
}

export interface PluginContainerResource {
  id: string;
  pluginId: string;
  name: string;
  path: string;
  order: number;
  content?: unknown; // 仅在 readContainer 时返回
}
```

容器是资源注册表：成员可被索引、显式导入或由用户选择。容器状态与解析逻辑抽离为 Pinia `useContainerStore`，提供响应式容器列表与背景媒体解析。

### 2.4 插入条件

插件文件编辑器使用列表编辑器配置条件，最终保存为 `insertion.condition` 或 `insertion.conditionPath`。解析容器成员时条件同步执行。环境包含资源的作用域 `imports`、生成环境，以及 `include`、`exclude`、`probability` 等逻辑函数。

## 3. 文件与目录语义约定

### 3.1 约定配置文件格式

#### manifest.json (唯一配置)
```ts
export type PluginManifest = {
  group: { id: string; title: string };
  content: {
    id: string;
    title: string;
    description: string;
    component: "Switch" | "Checkbox" | "Input" | "Textarea" | "Select" | "Slider" | "ModelSelect" | "MediaSelect" | "PathSelect" | string;
    props?: Record<string, unknown>;
    value: unknown; // 合法 JSON 值
  }[];
}[];
```
- **`generation/model`**：模型引用使用 `provider/modelId/thinkingLevel`；值为空时继承全局默认聊天模型。
- **`appearance/background`**：由内置核心 Plugin 保存，值是去掉扩展名的插件内路径 ID。

#### 生成入口 (generatePath) 容器
生成流程入口不再置于 `manifest.json` 中，而是声明为 `generatePath` 单选容器。插件通过将其 JavaScript 脚本文件的 `insertion.target` 设置为 `"generatePath"` 参与该容器。只有一个插件带有本地 `generatePath` 容器贡献时，才能作为主要插件。

#### containers.json (容器定义)
```ts
export interface PluginContainerDefinitions {
  containers: Omit<PluginContainer, "pluginId" | "resources">[];
}
```

### 3.2 约定资源格式
- **`AGENTS.md`**：可选的 Agent 说明文件。
- **`*.chat.json`**：带角色上下文资源 (`{ message: Array<{ role, content }> }`)。
- **`*.data.json`**：(属于 DATA 容器) 可水合的数据定义，随着容器与引用按需解析。
- **`regex.json`**：(属于 REGEX 容器) 排序正则规则。
- **`action/`**：接受 `.js`、`.md`、`.vue` 命令文件。
- **`background/`**：用户背景素材，注册到 `background` 容器。
- **`temp/`**：Agent 运行时生成文件的存放目录。

## 5. 显式导入与 Sandbox API

### 5.1 顶层 FS 函数与路径前缀 (URI Standard)
- **`@/`**：映射到当前插件根目录。
- **`@<pluginId>/`**：映射到目标插件根目录。
- **`read(path)`** / **`write(path, content)`** / **`edit(path, find, replace)`** / **`ls(path)`** / **`exists(path)`** / **`mkdir(path)`** / **`move(from, to)`** / **`remove(targetPath)`** / **`grep(path, pattern)`**
- **`import(path, environment?)`**：导入并解析资源。已清除旧版本 `imports.resource`/`imports.config` 残留正则，支持标准 `import(...)` 语法。
- **`run(path, environment?)`**：执行 JavaScript 脚本。
- **`extractYAMLFormatter(input: string | string[])`**：从文本或文本数组中提取 YAML frontmatter 或 YAML 代码块，返回 `{ result: string, formatter: object[] }[]`，由插件层自由组合。

### 5.2 容器与 Pinia API (useContainerStore)
- 容器逻辑抽离为 Pinia `useContainerStore`，提供响应式 `activeContainers` 和 `activeBackgroundResource` 状态，移除原有自定义事件发布订阅机制。
- Sandbox 内保留 `container.list()` / `container.get()` / `container.read()` / `container.import()` / `config.get()` / `config.set()`。

---

## 6. Conversation 与生成流程边界

1. 创建空的助手目标消息。
2. 构建 Sandbox 环境，并由 Pinia `useContainerStore` / Plugin Resolver 索引可见插件与容器。
3. 执行主插件的 `generatePath` 容器入口脚本。
4. 生成期对 Plugin/Data 的变更作为 JSON Edit 记录写入当前消息的 Overlay，不影响基础插件树。
